## 現行 v3 — 2026-09-09 ラッチ改良

Ø16 ノブ頭と容器の干渉を避けるため、円すい底の頭ポケットを廃止し、平面座を y=24 mm に移した。
ラッチ軸 x=62、z=40/170、通し穴 Ø5.4、コア合わせ面、HP 座、ヒンジは維持。
ボス高さ34 mm、追加8 mmの下面は45°補強とした。

**ボルトは再選定が必要**。首下長は `24 + 必要ねじ掛かり長 + ワッシャ厚`。

**v2のFEA PASSをv3に引き継がない**。平面座での荷重導入とボルト長を更新した強度評価は未実施。
印刷姿勢は従来どおり+Z上、底z=-17。中帯・上帯下面のサポート検討は継続。
検証: `python scad/lib/verify_child_frame2_latch.py`。

**全 7 ケース 強度 PASS / 剛性 PASS。最小は L3 の SF p99.5 = 4.49、最大たわみは L3 の 0.427 mm。**

- 細かくすると**たわみが下がり SF が上がる**方向に動いた。理由は数字で言える:
  **voxel 2.0 は部品の 12.6% を取りこぼしている** (23,105 × 8 = 184,840 mm³ / 実体 211,519 mm³)。
  6 mm のキール・座面板・ラッチ柱が 2 ボクセルに満たない場所で痩せるためで、
  voxel 1.33 では 90,215 × 2.353 = 212,240 mm³ = **100.3%** と実体に一致する。
  つまり voxel 2.0 の値 (L3 SF 3.95 / L4 たわみ 0.811 mm) は**保守側の下限**、
  voxel 1.33 の値が実形状。どちらでも合格基準は満たしている
- **`mesh resolution` は voxel 1.33 でも FAIL する (thin 2.66 mm = 2 ボクセル = 格子の下限)。**
  これ以上細かくしても同じことが起きる: 本部品の真の最薄部は
  (a) **HP40 インサートボスの壁 (Ø12 − Ø6.4)/2 = 2.8 mm** — `scad/lib/hardpoint.scad` の規格値で
  本部品固有ではない (コアフレーム v5 も同じ)、(b) **ノブ頭ポケット (Ø18) 脇のボス壁 1 mm**
  (x 71..72。−X 側は内腔差分で壁自体が無い — 要確認 9)。
  これらを 3 要素で解くには voxel ≤ 0.5 mm (要素数 1700 万) が要り、実用的でない。
  **「典型断面」は voxel 1.33 で 5.32 mm / 4.0 要素 = 基準を満たしている**ので、
  荷重を担う部材の応力は解けていると判断した


#### 最悪要素の読み方 (worst element)

判定は **p99.5** で行う。最悪要素の値は「人が見に行くべきか」を決めるための情報:

- **L3 の 1.80 @ (65, 15, 198)** / **L4 の 1.34 @ (−17, 67, 186)** — 荷重を掛けた領域
  (ラッチボス / HP 座) の内部か縁。ボクセル格子の階段状の角に出る典型的なアーチファクト。
  最適化形状も同じ場所で worst 2.87 (L3) を出していた
- **L2Lf 3.01 @ (±21, 63, 0) / L2Ls 2.06 @ (21, 65, 0)** — こちらは**アーチファクトではない**。
  2 つの独立したケースが同じ位置を指し、しかも荷重点ではない。位置は
  **縦キール (t6) が下把持帯の外面 (r=64.35 の曲面) に着く入隅**で、`.scad` では
  設計規約 1 によりフィレットを付けられない。**Fusion 側で R3〜R5 のフィレットを付けるのが
  想定される処置**。p99.5 は 7.79 / 8.08 と十分なので設計変更はしていない

## 干渉チェック (`.scad` 冒頭の assert)

1. **把持・ポケット**: リップの掛かり ≥1 mm (下=キャップリム / 上=ドームリング)、ポケット径クリア ≥0.3、
   下帯がコーン上端 +2 より高い、上帯がポケットより 4 mm 以上下から始まる、中央帯がポケットに掛からない、全高 ≤250
2. **ヒンジ**: ナックル壁厚 ≥4.5、ざぐり周囲 ≥3、腕ブロックがヒンジ開閉スイープ (x<−72 で y>18) に入らない、
   腕の内端が内腔に届く、**ゲート/コアのナックルが遊び 0.4 で互い違いに噛み合う (4 本)**、
   **腕ブロックがコア側ナックル柱と z で重ならない (総当り 3×2)**
3. **ラッチ + ノブボルト挿入通路** ← v1 の致命的欠陥を潰した箇所 (下記)
4. **前面 HP + キール + ブリッジ**: 座面 y = r_out+10、インサート穴がシェル外面に食い込まない、
   インサートボス底肉 ≥3、キールがインサート列の直下・座面板の幅内・HP-L のケーブル穴から 1 mm 以上・
   ブリッジ外側域 (\|x\|≥27) の外、キール後端が内腔でトリムされる、HP 座同士が z で重ならない (総当り)、
   **HP 座がブリッジ内側占有域 z 42.3..74 と重ならない (3 個とも)**、上ポケット↔HP4 穴、下ポケット↔HP-L 穴

### ノブボルト挿入通路 (前ワーカー §7-1 の指摘への対応)

v1 は **ノブボルト頭 Ø16 をポケットに挿入できなかった** (y=17 の断面でシェルが x 56.9..62.1 を塞いでいた)。
v2 では通路を「obstacle として最適化に空けさせ、部材側を y ≤ 16 に切り上げる」方式で確保した。

- 通路の定義: **Ø24 の円柱、軸 = Y、中心 (x=62, z=40) と (x=62, z=170)、y ≥ 16 (ボス前面) から +Y へ 30 mm**
  (`knob_acc_d` / `knob_acc_h`、`topo_v1/child_jaw_gate_v1.scad` の `finger_room()` と二重定義)
- **空け方**: シェルを通路の位置から消したのではなく、**ラッチ側の部材を全部 y ≤ 16 に収めた**。
  ラッチ柱 y 0..16、ラッチボス y 0..16 (= 通路の口と面一)。ここに通路が食い込む余地が無い
- **assert の内容** (通路と重なりうる部材ごとの距離検査。OpenSCAD は「空虚」を測れないため):

  | 部材 | 検査 |
  |---|---|
  | ラッチ柱 | `lf_t <= knob_y0` (16 ≤ 16) |
  | ラッチボス | `boss_y1 <= knob_y0` (16 ≤ 16) |
  | 把持帯 ×3 (全周の殻なので z で離すしかない) | 各帯 × 各 latch_z で `band_z1 <= z−12` または `band_z0 >= z+12`。実際の余裕 = 下帯 22 / 中帯 40 / 上帯 18 mm |
  | ヒンジ腕ブロック | `hf_x1 <= 62−12` (−50 ≤ 50) |
  | 縦キール | `keel_cx + keel_w/2 <= 62−12` (23 ≤ 50) |
  | HP 座 + インサートボス | 座の最大 x (26) ≤ 50 |

- 保険として `knob_channel()` を実際に `difference()` でも引いてある (assert が漏れても材料が残らない)
- **`knob_acc_d = 24` は仮値** — 実際のノブの直径・回転に要る指の空間で決まる (要確認 4)

## 部品外の考慮

- **購入品**: ヒンジピン Ø5×約240 (ステンレス棒 or M5 長ボルト) + E リング、M5 ノブボルト ×2、
