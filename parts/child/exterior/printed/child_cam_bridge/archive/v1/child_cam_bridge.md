# child_cam_bridge — カメラブリッジ (HP4/HP5 外付け、横向き 2 台)

外装改善要件 (2026-09-04, [要件書](../../../../../docs/子機外装_改善要件.md) §3.2) と、
同日のコーディネータ決定 1/2/3、および**同日の取合い修正決定** (後ウェブ/デッキ/
中央柱/キール再設計、ケース幅の変数誤り修正、端板高さ修正) に基づく部品。
`child_jaw_gate` の HP4/HP5 (HP40 規格) に M5×8 で外付けし、`child_cam_mount` ×2 を
横向きで保持する。輸送時はこの 8 本を外してブリッジごと取り外す (C7)。

## 役割

`child_jaw_gate` の HP4 (z170) / HP5 (z100) 座に中央柱で共締めし、左右へ張り出した
ウイングの上に `child_cam_mount` (横向き、90° 回転) を M5×4 ずつ載せる。
左右カメラのレンズは x=±75。

## デッキ高さの導出 (決定 1、変更なし)

```
deck_top = lens_z − cm_lens_off_bot − cm_fin_x1 = 125 − 42.05 − 30 = 52.95
deck_bot = deck_top − deck_t(8) = 44.95
case_z0 (register 面 = ケース底) = deck_top + fin_x1 = 82.95
case_z1 (ケース上端) = case_z0 + case_h(84.1) = 167.05  (lens 125 = 中点、検算 OK)
```

## 取合い修正 (2026-09-04、4 点)

前回ビルドはコーディネータ指摘の通り 4 箇所で誤り/干渉があった。すべて修正し
再ビルドで確認済み (assert 全通過、solids=1、watertight)。

**1. 後ウェブがケースに侵入 + HP5 シェルフと重なる**
→ 後ウェブを **x 27..120、y 67..73 (t6)、z 44.95..160** に変更。
ケース背面 (`case_y0 = mount_y0 − case_d/2 = 74.1`) の 1.1mm 手前で止め、
ゲート殻 (r64.35) との離隔は x=27 で `sqrt(64.35²−27²) = 58.4` →
`67 − 58.4 = 8.6mm ≥ 8` (assert)。

**2. 接続の作り直し (旧設計は 1×2mm の細片で吊っていた)**
- デッキを **x −120..120 で連続、y 67..124、z 44.95..52.95** に変更 (中央も含む)。
  HP-L シェルフ上端 (z40) との隙間 4.95mm、ゲート殻 (x=0 で y64.35) との隙間
  2.65mm を assert
- 中央柱 (x±25、y 74.35..80.35) を **z 44.95..195** まで下へ延長し、デッキ・
  キールと直接 union (旧: HP4/HP5 個別パッド+20mm 連結材 → 新: 単純な XZ 板 1 枚
  から M5×8 を差し引く方式に簡略化)
- **キール** (x±25、y 67..80.35、z 44.95..74) を追加。HP5 シェルフ下端 (z75) に
  1mm、HP-L シェルフ上端 (z40) との関係も assert。後ウェブと y67..73/z44.95..74
  で面接合、デッキ・中央柱とも直接重なりを持つ (面接触ではなく実体積の重なりで
  接続を保証)
- 荷重経路: ウイング −Z 荷重 → 後ウェブ (面内) → キール → 中央柱 (XZ 板、
  M_y に対し面内) → HP5/HP4 の M5×8

**3. ケース幅の変数間違い**
`case_outer_x = lens_x + cm_case_h/2` (=117.05、高さを使う誤り) →
**`case_outer_x = lens_x + cm_case_w/2 = 75 + 47.35 = 122.35`** (横向きでは
ケース幅 `case_w`=94.7 が機体 X)。`child_side_bumper.scad` も同時に修正 (二重定義)。

**4. 端板がケース底面より高い**
端板 (旧 z1=85) がケース底面 (82.95) の上 2.05mm に食い込んでいた。
**端板 z1 = 80、前ウェブ z1 = 80** に変更 (ケース底面の 2.95mm 手前)。
FOV: `atan((125−80)/(128−120)) = atan(45/8) = 79.9°`、余裕 2.4° に改善
(旧 1.2° → 2.4°)。バンパのフランジ/ボルト z (`bump_bolt_z=65`) は
`end_plate_z1(80) − 2 = 78` 以下を assert (両ファイルで同値)。

**5. `bump_nut()` の穴長バグ (2026-09-04 追加修正)**
`check_asm_contacts.py` で `side_bumper_stbd`/`side_bumper_port` が `cam_bridge`
から **4.35mm 浮いている (FLOATING)** ことが判明。原因はバンパ側 (下記
`child_side_bumper.md` 参照) と、併せて見つかったブリッジ側の別バグ:
`bump_nut()` のクリアランス穴が `h = wing_x1 − end_plate_t − nut_dep = 110mm`
になっており、端板の厚さ (6mm) を大きく超えてウイング中央近くまで穴が貫通していた
(ビルド・assert は通っていたため気付いていなかった)。**端板厚 (`end_plate_t=6`)
の範囲内**に収まるよう修正し、左右で穴の向きが逆になる問題も
`ang = -90*sign` (符号付き回転角) で解消した。

検査**を追加した (`box_overlap()` 関数、9 個のブリッジ部材ボックス × 7 個の
除外ボックスの全 63 組):

- (a) ケース直方体 (x 27.65..122.35, y 74.1..120, z 82.95..167.05、左右鏡像)
- (b) ゲート HP シェルフ 3 個 (x ±25, y 62.35..74.35, z 中心 ±25、HP4/HP5/HP-L)
- (c) マウント本体の機体footprint (x 58..92, y 75.05..119.05, z 52.95..82.95、左右鏡像)

境界の共有面 (完全一致) は非干渉として扱う (厳密不等号)。ビルドで 63 組すべて
PASS を確認 (assert が 1 つでも落ちればビルドが止まる)。

- デッキ下端 ≥ HP-L 座上端+2 (42) / 最上端 ≤ 195 (HP4 座上端)
- 全幅 (デッキ/ウイング先端) ≤ 120 (240 枠)
- デッキ・キールとゲート殻の離隔 (x=0 で 2.65mm、後ウェブは x=27 で 8.6mm)
- 後ウェブがケース背面に 1mm 以上手前で止まる
- キール上端が HP5 座下端の 1mm 手前 / キール下端が HP-L 座の 2mm 以上上
- マウント M5 穴のデッキ縁距離 ≥3mm (前後とも)
- 端板・前ウェブがケース底面 (82.95) の 1mm 以上手前
- **FOV**: 前ウェブ最近接点 (x=lens_x, z=80, y=128) が対角半角 77.5° の外

## 荷重ケースと安全率 (L2 輸送 300N、3 方向)

**ウイング断面** (デッキ t8 + 後ウェブ t6 + 前ウェブ t6 の合成断面、根 x=27
〜先端 x=120、L=93mm) は前回評価どおり大きな余裕がある (−Z 曲げ ~1.1MPa、
−Y 曲げ ~1.8MPa、いずれも許容 12MPa に対し数倍の安全率。後ウェブが薄くなった
分 (旧 t8.5→新 t6) 若干応力は上がるが、桁が変わるほどではない)。

**根元断面 (x = ±25、中央柱 + キール + デッキ) の評価** (`M_y = 300 N × 95 mm = 28,500 N·mm`、
ウイング先端の −Z 荷重による Y 軸まわりの曲げ)。

M_y は中央柱 (XZ 面の板、t6 × z 44.95..195) を**面内**で曲げる。板の曲げ深さは
**Z 方向の 150 mm** であって板厚方向の 50 mm ではない (2026-09-04 の初回評価は誤って
幅 50 を深さに取り、σ 11.4 MPa / SF 1.05 と報告していた。訂正):

| 項目 | 値 |
|---|---|
| I (中央柱のみ、b=6 (y 厚)、h=150 (z 深さ)、b·h³/12) | 1.69 × 10⁶ mm⁴ |
| c (最遠繊維 = 深さの半分) | 75 mm |
| σ = M·c/I | **1.3 MPa** |
| 応力方向 | 機体 X〜Z の面内 (印刷 +Y up で層面内) |
| 許容 (面内 12 MPa) | → **PASS、安全率 ×9** (キール 13.35×29 とデッキ 57×8 を足すとさらに下がる) |

`quick_strength beam --L 95 --b 6 --t 150 --F 300 --in-plane` 相当。
実効的に最も余裕が少ないのは HP5/HP4 の **M5 ボルト 8 本の引抜き** (M_y をボルト対の
偶力で受ける: 28,500 / 40 mm ピッチ ≈ 710 N を 2 本で分担 → 355 N/本。M5 熱圧入
インサートの引抜き耐力は PETG で 400〜800 N 程度 → **インサートの引抜き試験を推奨**)。

## 部品外の考慮

- `child_cam_mount` 本体・防水ケースは本部品に含まない (`placement.json` で別配置)
- HP4/HP5 の M5×8 は中央柱を Y 軸方向に貫通する穴で、座面前方からアクセス可能
- バンパ (`child_side_bumper`) の M5×2×2 は端板フランジのナットトラップで受ける
- FOV 余裕は 2.4° に改善したが、`lens_off_bot`/`case_h`/`case_w` の実測でこの
  余裕が変わるため、実測後に必ず再検査
- 輸送時は M5×8 を外してブリッジごと (カメラ・マウント・バンパも道連れで) 取り外す

## 要確認

1. `child_cam_mount` の `lens_off_bot`/`case_h`/`case_w`/`fin_x1` 実測で
   `deck_top`/`case_z0`/`case_z1`/`case_outer_x`/FOV 余裕が連動して変わる。
   実測後は必ず本部品も再ビルド・再検査すること
2. **HP4/HP5 の M5 インサート引抜き (約 355 N/本、L2 300 N 時)** が実効的な律速。引抜き試験を推奨。(旧記述「中央柱根元 SF 1.05」は深さの取り違えで撤回)
3. FOV 余裕 2.4° はまだ実測待ちの仮値に依存。前ウェブをこれ以上前や高くしない
4. `mount_y0` (レンズがケース中央にあるという仮定) は推定値。実測で変わる可能性
5. 印刷姿勢 +Y up のオーバーハング 30.9% は自動最適化 (−X up, 5.8%) より悪い。
   サポート material 増加のトレードオフをスライサで最終確認すること
6. **解決済み (記録)**: `bump_nut()` の穴長バグ (110mm、意図せずウイング中央
   近くまで貫通) と、それに起因する `side_bumper_*` の 4.35mm FLOATING は
   2026-09-04 に修正・再検査で解消済み (`check_asm_contacts.py` で 0.09/0.13mm
   "ok"、penetration なし)
